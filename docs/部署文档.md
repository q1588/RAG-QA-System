# 🐳 部署文档

本系统支持**本机直跑**（SQLite，零依赖）与 **Docker 一键部署**（MySQL 8 + API 两个容器）。

---

## 一、架构说明

```
宿主机（已安装并运行 Ollama：qwen2.5:3b + nomic-embed-text）
  │
  ├── Docker 网络内：
  │     ├── rag_mysql   MySQL 8.0（utf8mb4，healthcheck 就绪探测）
  │     └── rag_api     Python 3.13 + FastAPI（依赖 db 健康后才启动）
  │
  └── Ollama 通过 host.docker.internal 供容器内调用
```

- API 容器通过 `OLLAMA_BASE_URL=http://host.docker.internal:11434` 访问宿主机 Ollama（仅 Docker Desktop for Windows/Mac 支持该域名）。
- 三个数据卷：`mysql_data`（数据库）、`upload_files`（上传文档）、`chroma_store`（向量库），删除容器不丢数据。

---

## 二、本机直接运行（Windows 开发）

```bash
# 1. 安装依赖
cd RAG-QA-System
../.venv/Scripts/pip install -r requirements-dev.txt   # 含 pytest（跑单测用）

# 2. 确认 Ollama 已运行且模型就绪
ollama list        # 应看到 qwen2.5:3b 与 nomic-embed-text

# 3. 启动（首次启动自动建表）
../.venv/Scripts/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 4. 访问
#    聊天页    http://127.0.0.1:8000/
#    接口文档  http://127.0.0.1:8000/docs
```

> 数据库默认 `sqlite+aiosqlite:///./app.db`，在项目根目录生成，无需额外安装 MySQL。

## 三、Docker 部署（生产形态：MySQL + API）

### 3.1 前置条件

- 安装 **Docker Desktop**（Windows），并启动；
- 宿主机安装 **Ollama** 且已 `ollama pull qwen2.5:3b`、`ollama pull nomic-embed-text`；
- 确认 8000 端口未被占用。

### 3.2 一键启动

```bash
cd RAG-QA-System
docker compose up -d --build
```

首次构建会下载基础镜像并安装依赖，约需几分钟。完成后：

```bash
docker compose ps          # 两个服务均应为 Up / healthy
docker compose logs -f api # 查看 API 日志
```

### 3.3 验证

```bash
# 健康检查
curl http://localhost:8000/health   # 期望 {"status":"ok","database":"ok"}

# 注册一个用户
curl -X POST http://localhost:8000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 打开聊天页 / docs 开始使用
```

### 3.4 常用运维命令

```bash
docker compose down                 # 停止（保留数据卷）
docker compose down -v              # 停止并删除数据卷（数据清空，慎用）
docker compose logs -f db           # 查看 MySQL 日志
docker exec -it rag_mysql mysql -uroot -p rag_db   # 进入 MySQL
```

### 3.5 配置说明（`.env` / compose 环境变量）

| 变量 | 说明 | 默认 |
|---|---|---|
| `DATABASE_URL` | 数据库连接串（compose 内已切 MySQL） | sqlite（本地） |
| `JWT_SECRET` | JWT 签名密钥，**生产必须更换** | 开发用随机串 |
| `OLLAMA_BASE_URL` | Ollama 地址 | 本机/`host.docker.internal` |
| `EMBED_MODEL` / `LLM_MODEL` | 向量 / 生成模型 | nomic-embed-text / qwen2.5:3b |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码（compose 内） | root123456 |

生产环境建议在启动前设置强密钥：

```bash
export JWT_SECRET="$(openssl rand -hex 32)"
export MYSQL_ROOT_PASSWORD="$(openssl rand -hex 16)"
docker compose up -d --build
```

## 四、常见问题排查

| 现象 | 原因与处理 |
|---|---|
| API 起不来 / RAG 报连接拒绝 | Ollama 未运行或 `OLLAMA_BASE_URL` 不对；宿主机先 `ollama serve`，容器内检查能否访问 `host.docker.internal:11434` |
| 问答答非所问 / 说不知道 | 知识库还没有文档：先 `upload` + `vectorize`；或问题与文档内容无关 |
| 模型没拉取报 404 | `ollama pull qwen2.5:3b`、`ollama pull nomic-embed-text` |
| MySQL 一直 unhealthy | 首次初始化较慢，等待 `docker compose ps` 显示 healthy 后再看 API |
| Windows 下 curl 中文乱码 | 终端编码问题，改用 `/docs` 或 Postman/前端页面（UTF-8） |

## 五、数据初始化与备份

- **建表**：API 启动时 `lifespan` 自动 `create_all`（幂等）；也可手动 `python -m app.db.init_db`。
- **备份**：
  ```bash
  docker exec rag_mysql mysqldump -uroot -p rag_db > rag_db.sql
  ```
- **导入文档**：把 txt/md/pdf/docx 放进 `upload_files/`（或走 `/api/rag/upload` 接口），然后调用 `/api/rag/vectorize` 向量化入库。
