# 🐳 部署文档

本系统支持**本机直跑**（SQLite + Milvus Lite，零外部服务）与 **Docker 一键部署**（MySQL 8 + Milvus + API）。

---

## 一、架构说明

`
┌────────────── 宿主机 / 云服务器 ──────────────┐
│  .env 配置在线模型 API（Embedding + LLM）      │
│  （SiliconFlow / OpenAI / 阿里云百炼 / DeepSeek）│
└──────────────────────┬────────────────────────┘
                       │ HTTPS（OpenAI 兼容协议，异步）
┌──────────────────────▼────────────────────────┐
│ Docker 网络内：                                │
│   ├── rag_mysql   MySQL 8.0（utf8mb4，业务库）  │
│   ├── milvus-etcd / milvus-minio / milvus     │
│   │              Milvus 独立服务（向量库）      │
│   └── rag_api     Python 3.13 + FastAPI        │
└───────────────────────────────────────────────┘
`

- 业务数据（用户/会话/消息）在 MySQL；向量库在 Milvus（etcd 元数据 + MinIO 对象存储）。
- 模型调用走**在线 API 服务**（OpenAI 兼容协议，异步并发），不再依赖宿主机 Ollama；
  若内网环境希望离线，可把 `EMBEDDING_PROVIDER` / `LLM_PROVIDER` 改为 `ollama` 并配置 `OLLAMA_BASE_URL`。
- 三个数据卷：`mysql_data`、`milvus_data`（含 etcd/minio 卷）、`upload_files`，删除容器不丢数据。

## 二、本机直接运行（Windows 开发，零 Docker）

### 2.1 安装依赖

`
cd RAG-QA-System
../.venv/Scripts/pip install -r requirements-dev.txt   # 含 pytest（跑单测用）
`

### 2.2 配置 .env（参考 .env.example）

至少配置一组在线模型密钥（SiliconFlow 推荐，国内直连）：

`
EMBEDDING_PROVIDER=openai
EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1
EMBEDDING_API_KEY=sk-xxxxxxxx
EMBED_MODEL=BAAI/bge-m3

LLM_PROVIDER=openai
LLM_BASE_URL=https://api.siliconflow.cn/v1
LLM_API_KEY=sk-xxxxxxxx
LLM_MODEL=Qwen/Qwen2.5-7B-Instruct
`

向量库默认 Milvus Lite 单文件（`MILVUS_URL=./milvus_store/rag.db`），无需任何服务，首次向量化自动创建。

### 2.3 启动

`
../.venv/Scripts/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
`

- 聊天页 http://127.0.0.1:8000/ ；接口文档 http://127.0.0.1:8000/docs
- 首次启动日志会打印 Milvus 向量库初始化结果；若连不上（如远程 Milvus 未启动）会告警但不阻断服务。

### 2.4 验证

`
# 健康检查（含向量库状态）
curl http://127.0.0.1:8000/health    # {"status":"ok","database":"ok","vector_db":"ok"}

# 单测
../.venv/Scripts/python -m pytest tests -v

# RAG 召回评估（离线自检，无需 Key；真实效果用 --embeddings real）
../.venv/Scripts/python.exe scripts/eval_rag.py --embeddings fake
`

## 三、Docker 部署（生产形态：MySQL + Milvus + API）

### 3.1 前置条件

- **Docker Desktop**（Windows）或 Linux Docker，并启动；
- 网络可拉取镜像（若 docker.io 不可达，请在 Docker Desktop → Settings → Docker Engine 配置 registry-mirrors，例如 `https://docker.m.daocloud.io`）；
- 准备 `EMBEDDING_API_KEY` / `LLM_API_KEY`（SiliconFlow / OpenAI / 百炼等）。

### 3.2 一键启动

`
cd RAG-QA-System
export EMBEDDING_API_KEY=sk-xxx LLM_API_KEY=sk-xxx   # 或写入 .env
docker compose up -d --build
`

首次构建会拉取基础镜像与 Milvus 相关镜像、安装依赖，约需几分钟。完成后：

`
docker compose ps          # db/milvus/api 均应为 Up / healthy
docker compose logs -f api # 查看 API 日志
`

### 3.3 验证

`
curl http://localhost:8000/health   # 期望 {"status":"ok","database":"ok","vector_db":"ok"}

curl -X POST http://localhost:8000/api/auth/register   -H "Content-Type: application/json"   -d '{"username":"admin","password":"admin123"}'
`

### 3.4 常用运维命令

`
docker compose down                 # 停止（保留数据卷）
docker compose down -v              # 停止并删除数据卷（数据清空，慎用）
docker compose logs -f db           # 查看 MySQL 日志
docker compose logs -f milvus       # 查看 Milvus 日志
docker exec -it rag_mysql mysql -uroot -p rag_db   # 进入 MySQL
`

### 3.5 配置说明（.env / compose 环境变量）

| 变量 | 说明 | 默认 |
|---|---|---|
| `DATABASE_URL` | 业务数据库连接串（compose 内已切 MySQL） | sqlite（本地） |
| `JWT_SECRET` | JWT 签名密钥，**生产必须更换** | 开发用随机串 |
| `MILVUS_URL` | Milvus 地址：本地文件路径 = Milvus Lite；http(s) = 独立服务 | ./milvus_store/rag.db |
| `MILVUS_COLLECTION` | 向量集合名 | rag_docs |
| `EMBEDDING_PROVIDER` | openai（在线 API）/ ollama（本地） | openai |
| `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` / `EMBED_MODEL` | 在线 Embedding 服务 | SiliconFlow / BAAI/bge-m3 |
| `LLM_PROVIDER` / `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 在线 LLM 服务 | SiliconFlow / Qwen2.5-7B-Instruct |
| `CHUNKING_STRATEGY` | 切块策略：recursive / semantic / hybrid | recursive |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码（compose 内） | root123456 |

生产环境建议在启动前设置强密钥：

`
export JWT_SECRET="$(openssl rand -hex 32)"
export MYSQL_ROOT_PASSWORD="$(openssl rand -hex 16)"
export EMBEDDING_API_KEY="sk-xxx" LLM_API_KEY="sk-xxx"
docker compose up -d --build
`

## 四、RAG 评估（上线前量化召回）

`
# 真实模型效果基线（用 .env 配置的 Embedding API）
../.venv/Scripts/python.exe scripts/eval_rag.py --embeddings real --strategies recursive,semantic,hybrid --top-k 3,5

# 输出：控制台 Markdown 表格 + eval_report.json（每题检索明细 + 指标）
`

把首次结果存为基线；之后每次调整切块参数 / Embedding 模型 / Top-K 后重跑对比，
用 Hit@K / Recall@K / Precision@K / MRR@K 的数值变化代替肉眼判断。

**重要提醒：**

- `--embeddings fake` 仅用于流程验证（确定性、可复现），不代表真实效果；上线基线请用 `--embeddings real`。
- **切换不同维度的 Embedding 模型后必须重建向量集合**：否则写入会报 409（维度不匹配）。
  重建方式：向量化时携带 `rebuild=true`（如 `POST /api/rag/vectorize {"filename":"x.md","rebuild":true}`），
  或删除本地 `milvus_store/`（Docker 环境清空 milvus 卷）后重新向量化全部文档。
- `RAG_RELEVANCE_THRESHOLD` 默认 0.5 为初始值：不同 Embedding 模型的无关文本余弦基线不同
  （如 bge-m3 常在 0.3~0.6）。用真实 API 跑一次评估，查看 eval_report.json 中的检索分数分布后校准。

## 五、常见问题排查

| 现象 | 原因与处理 |
|---|---|
| API 起不来 / RAG 报 503「无法连接外部模型服务」 | `EMBEDDING_API_KEY` / `LLM_API_KEY` 未配置或地址不可达；检查 .env 与网络 |
| 报「未配置 EMBEDDING_API_KEY」 | 在线模式必须填 Key；内网想离线请改 `EMBEDDING_PROVIDER=ollama` 并确保 Ollama 运行 |
| /health 显示 `vector_db:error` | Milvus 未启动或 `MILVUS_URL` 不对；Docker 部署等待 milvus healthy，本地检查 milvus_store 目录可写 |
| 问答答非所问 / 说不知道 | 知识库还没有文档：先 upload + vectorize；或问题与文档内容无关（低于相关性阈值如实回答） |
| Docker 拉镜像失败 | docker.io 被墙；配置 registry-mirrors（如 docker.m.daocloud.io）后重启 Docker Desktop |
| Windows 下 curl 中文乱码 | 终端编码问题，改用 /docs 或 Postman/前端页面（UTF-8） |

## 六、数据初始化与备份

- **建表**：API 启动时 lifespan 自动 create_all（幂等）；也可手动 `python -m app.db.init_db`。
- **向量库**：Milvus Lite 模式下直接备份 `milvus_store/` 目录；Docker 模式下备份 `milvus_data` 卷。
- **备份业务库**：
  `
  docker exec rag_mysql mysqldump -uroot -p rag_db > rag_db.sql
  `
- **导入文档**：把 txt/md/pdf/docx 放进 `upload_files/`（或走 `/api/rag/upload`），然后调用 `/api/rag/vectorize` 向量化入库（可指定切块策略）。
